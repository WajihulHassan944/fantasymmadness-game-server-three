# Phase 2 SEO + Performance Backend Update

This update keeps the existing backend structure intact and adds a separate `seo-performance-phase2.js` module for SEO, sitemap, pagination, schema, and approval workflows.

## Added public APIs

- `GET /api/public/seo/health`
- `GET /api/public/seo/robots-data`
- `GET /api/public/seo/sitemap-data`
- `GET /api/public/seo/metadata`
- `GET /api/public/seo/schema`
- `GET /api/public/seo/internal-links`
- `GET /api/public/fights`
- `GET /api/public/fights/:id`
- `GET /api/public/blogs`
- `GET /api/public/blogs/:id/related`
- `GET /api/public/fighters`
- `GET /api/public/wrestlers`
- `GET /api/public/pro-wrestling/matches`
- `GET /api/public/videos`
- `GET /api/public/leaderboards`

These APIs include pagination metadata and short public cache headers so Phase 3-5 frontend work can improve SEO and performance without replacing legacy routes.

## Added admin APIs

- `GET /api/admin/seo/metadata`
- `POST /api/admin/seo/metadata`
- `POST /api/admin/seo/apply`
- `GET /api/admin/seo/swarm-reports`
- `POST /api/admin/seo/internal-links/preview`
- `GET /api/admin/seo/implementation-roadmap`

These routes allow admins/frontend to store, review, and apply SEO recommendations generated by the swarm.

## Added collections

- `SEOPageMetadata`
- `SEOAuditReport`

The collection can hold metadata for pages/entities that do not currently have native SEO fields in their original schema.

## Apply behavior

- Blog SEO can update `metaTitle` and `metaDescription`.
- Pro wrestler SEO can update `seo.title`, `seo.description`, and `seo.keywords`.
- Pro wrestling match SEO can update `seo.title`, `seo.description`, and `seo.keywords`.
- Other entity/page metadata is stored in `SEOPageMetadata` for frontend rendering in later phases.

## Safety

- No existing route was removed.
- No sensitive wallet, prediction, payout, or settlement logic was changed.
- Swarm recommendations still require backend/admin approval before being applied.
